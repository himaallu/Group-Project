# R2 · Reranker + entities (Rathi, Tue 17 Nov 2026)

- Fine-tuned `BAAI/bge-reranker-v2-m3` (1 epoch, 20k pairs: own snippet = 1, random other claim's snippet = 0; lr 2e-5, batch 16, max len 256, fp16, seed 42) with a plain PyTorch loop (`src/retrieval/train_reranker.py`), checkpoint every 20 min. 2.6 min on a Colab A100.
- Val (2,000 pairs, val splits only): accuracy 0.719 → 0.980, AUROC 0.980 → 0.998. The base model already ranks well (AUROC 0.98) but its scores are badly calibrated (own snippets average 0.44), so the 0.3 relevance cut in the twin rules only makes sense with the fine-tuned model. Note the task is easy (random negatives); it says nothing about hard, same-topic negatives.
- Relevance for every snippet of MultiFC + AVeriTeC train/val/test → `features/relevance_en.parquet`; `src/retrieval/rerank.Reranker.score(claim, snippets)` is reused by R3 (twin sources, `_C` donors) and R5 (offline index).
- Entities (spaCy, PERSON/GPE/LOC/ORG/DATE/EVENT, with character offsets so R3 can swap them in place) → `features/entities_en.jsonl`, one row per claim, one list per snippet (24,047 claims, 161,375 snippets). Colab now runs Python 3.13, so the notebook falls back to `en_core_web_lg` if `en_core_web_trf` cannot install; which one ran was not recorded in this run (the R3 run prints it).
