# R4 · NLI (Rathi) — summary

1. Built 32,658 weak NLI pairs (EN: supported claim + relevant snippet → entail, contradicted → contradict, `_B` swapped snippets → contradict, random snippet → neutral; AR: Youssef's 2,658 Y2 pairs) and fine-tuned mDeBERTa-v3 XNLI and XLM-R-large XNLI (seed 42, fp32; the checkpoint is stored in fp16 and had to be cast to fp32, otherwise every loss was NaN).
2. Fine-tuning raised weak-val macro-F1 0.40 → 0.76 but **dropped gold macro-F1** (mDeBERTa EN 0.37 → 0.12, AR 0.44 → 0.16; XLM-R the same), so the failure comes from the data, not the model.
3. Cause: the gold pairs are a claim's own snippets and 75% are neutral; v1 had no such examples, so the model learned "on-topic snippet → copy the claim's label", the same shortcut the project audits (worth reporting as a finding).
4. Fix (v2, coded + 9 unit tests): keep a weak pair only if the zero-shot model agrees (top class, p ≥ 0.5) and add own-snippet "hard neutrals"; `_B` pairs kept as they are. Run pending; it goes to `models/nli_v2` / HF `twincheck-nli-v2` / `features/nli_v2`.
5. Until v2 beats zero-shot on gold, `src/nli/score.py` (pipeline, R5 faithfulness, R6 demo) uses the zero-shot model; Himasri's experiments already use `features/nli_zeroshot`.
